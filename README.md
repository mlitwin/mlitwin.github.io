# antoninus.org

Matt Litwin's personal site — a static HTML site with no template engine and no
generated markup. Pages are lean, hand-authored HTML files that use two Web
Components (`<site-nav>`/`<site-footer>`) for shared chrome, plus a small set
of components (`<recent-posts>`, `<post-archive>`, `<post-nav>`) that read a
JSON manifest for post listings. All dynamic rendering — math, syntax
highlighting, heading anchors, site chrome — happens client-side at runtime.

## Getting started

```
npm install
npm start
```

`npm start` builds the site and serves `_site/` locally.

## How it's built

Two build steps, run in order (`npm run build` does both):

- **`npm run build-lib`** (`scripts/build-lib.js`) — collects and bundles
  third-party CSS/JS (PicoCSS, KaTeX, Prism, heading-anchors) from
  `node_modules` into `lib/`. `lib/` is generated, gitignored, and rebuilt on
  every build — never hand-edit it.
- **`npm run assemble`** (`scripts/assemble.js`) — copies `content/`, `lib/`,
  and `public/` into `_site/`. No parsing, no templating — just file copies.

## Directory structure

```
content/          hand-authored pages and posts (→ copied verbatim to _site/)
  blog/<slug>/     one directory per post, each an index.html
  index.html       home page
  blog.html        archive page
  resume.html
  404.html
  config.json      post manifest — see below
  CNAME            custom domain for GitHub Pages
templates/        starter files — copy these to create a new post or page
public/           site-authored CSS/JS + static assets (→ copied to _site/ root)
  css/site.css     thin override layer on top of Pico
  js/              site-nav/site-footer, post-list components
  img/, wsp/       images and the Web Sketchpad viewer assets
lib/              generated by build-lib.js — gitignored, never hand-edited
scripts/          build-lib.js, assemble.js, migrate.js
archive/          gitignored scratch area for posts not yet migrated/finished
```

## Adding a new post

1. Copy `templates/post.html` to `content/blog/<slug>/index.html`.
2. Fill in the title, date, and body. Math is raw LaTeX in `$...$` /
   `$$...$$` (rendered by KaTeX at runtime); code blocks are standard
   `<pre><code class="language-x">` (highlighted by Prism at runtime).
3. Add an entry to `content/config.json`'s `posts` array, in the position
   matching where it should sort — this drives the home page's recent-posts
   list, the archive page, and prev/next navigation. The array is
   hand-ordered newest-first; nothing sorts by date automatically.
4. Add a link to it from `content/blog.html` if it isn't already picked up
   by `<post-archive>` (it is, automatically, once it's in `config.json`).

## Migrating old Markdown posts

`scripts/migrate.js` is a one-time-per-post helper that converts a Markdown
post (YAML front matter + `marked`-rendered body) into the HTML shape above.
See the `posts` array at the top of the script for how to point it at a file.
Posts not yet worth migrating or finishing live in `archive/` (gitignored).

## Deployment

`.github/workflows/gh-pages.yml` runs `build-lib` + `assemble` on every push
to `main` and publishes `_site/` to the `gh-pages` branch via
`peaceiris/actions-gh-pages`. GitHub Pages is configured to serve that branch
at the custom domain in `content/CNAME`.
